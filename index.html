BlackboardSaveSystem

A decoupled, high-performance RAII save and state management framework for Unity. Designed with deterministic 4-level state partitioning, reference-counted BlackboardFile lifecycles, and zero-allocation gameplay state decorators via Tracked<T>.

4-Level Partitioning

Deterministic hierarchy: fileName → entityId → componentId → variableName → value.

RAII Smart Pointers

BlackboardScope anchors files in RAM on enable and serializes on zero reference count.

Pre-Eviction Event Flush

BlackboardFile.OnUnload notifies subscribed BlackboardClient leaf proxies before RAM eviction.

Zero-Allocation Gameplay

Tracked<T> caches backing values locally and synchronizes only during save/load operations.

1. Installation

You can integrate BlackboardSaveSystem into your Unity project via Unity Package Manager (UPM) or as a Git Submodule.

Option A: Unity Package Manager (UPM via Git URL)

  1. Open your Unity Project.
  2. Navigate to Window → Package Manager.
  3. Click the + button in the top-left corner and select Add package from git URL....
  4. Enter the repository URL:
https://github.com/ThiagoDAraujoS/BlackboardSaveSystem.git

Option B: Git Submodule

To add the repository as a Git submodule directly inside your Unity project's Assets directory:

git submodule add https://github.com/ThiagoDAraujoS/BlackboardSaveSystem.git Assets/ImportedToolsAndLibraries/BlackboardSaveSystem

2. Manager Setup

  1. Create a persistent manager GameObject in your initial boot scene (e.g., [SaveSystem]).
  2. Attach the SaveSystem component (which automatically requires and attaches Blackboard).
  3. Set coreFileNames in the Inspector to contain your global persistent save files (e.g., "core").
using BlackboardSaveSystem;
using UnityEngine;

public class GameInitializer : MonoBehaviour {
    private void Start() {
        // Initialize an active save session copying from a slot
        SaveSystem.InitializeSession("Slot_1");
    }
}

3. Configuring Scene Save Scopes (BlackboardScope)

BlackboardScope automates file acquisition and release using Unity's component lifecycle (OnEnable / OnDisable).

  1. Add a BlackboardScope component to a room, area root, or scene manager GameObject.
  2. In the Inspector, populate the fileNames list with the save files required by entities under this scope (e.g., "dungeon_level_01").

When the GameObject is enabled (or scene loaded), BlackboardScope acts as an RAII smart pointer that increments reference counts on its target BlackboardFile instances, loading them from disk into memory. When BlackboardClient components enable afterwards, they look up their BlackboardFile directly on the Blackboard and subscribe to its OnUnload event. When the last scope holding a reference to a file is disabled (dropping RefCount to 0), the BlackboardFile invokes OnUnload so subscribed clients flush their state before the file is removed from RAM and serialized to disk.

4. Entity State Binding (BlackboardClient & UniqueId)

To make any GameObject stateful and persistent across sessions:

  1. Attach a UniqueId component to the GameObject. A permanent GUID is generated automatically in the Unity Editor.
  2. Attach a BlackboardClient component to the same GameObject.
  3. Set the fileName field on BlackboardClient to match the file managed by the active BlackboardScope (e.g., "dungeon_level_01").

5. Creating Custom State Components (TrackedBehaviour & Tracked<T>)

To track custom gameplay variables on an entity with zero dictionary lookup overhead during gameplay:

  1. Create a script inheriting from TrackedBehaviour.
  2. Declare Tracked<T> fields passing a unique string key and default value in constructor initializers.
using BlackboardSaveSystem;
using UnityEngine;

public class PlayerStats : TrackedBehaviour {
    // Zero-allocation gameplay state decorators
    public Tracked<int>    Health     = new("health", 100);
    public Tracked<int>    MaxHealth  = new("maxHealth", 100);
    public Tracked<string> PlayerName = new("playerName", "Hero");

    public void TakeDamage(int damage) {
        // Implicit cast allows direct arithmetic and assignment
        Health.Value = Mathf.Max(0, Health - damage);
        Debug.Log($"[PlayerStats] Health is now {Health}");
    }
}

Tracking Position and Rotation (TrackedTransform)

Attach TrackedTransform to any GameObject needing persistent coordinates. It automatically handles NavMeshAgent warping via agent.Warp(position) when restoring position.

6. Saving, Sessions & Custom Metadata

Saving Active Session State

To commit live entity states and flush active RAM partitions to disk:

// Commit all loaded files to the _active_session working directory
await SaveSystem.CommitToActiveSessionAsync();

Custom Save Slot Metadata (MetadataProvider & SaveFileMetadata)

SaveFileMetadata is completely game-agnostic, storing custom UI variables in a dynamic Dictionary<string, string> Variables container and using the Null Object Pattern ("VOID") when a metadata file or key is unreadable: 

SaveSystem.MetadataProvider = () => new Dictionary<string, string> {
    ["location"]      = "Abandoned Outpost",
    ["characterName"] = "Protagonist"
};

// Reading save slots for UI lists (returns "VOID" via Null Object pattern if a key or meta.json is unreadable)
foreach (SaveFileMetadata meta in SaveSystem.GetSaveFileList()) {
    string location  = meta.Get("location");
    string character = meta.Get("characterName");
}

Direct Component State Access

You can also access active partitions directly from BlackboardClient:

BlackboardClient client = GetComponent<BlackboardClient>();

// Access partition for first component (index "0")
var partition = client.GetPartition(0);
partition["custom_flag"] = true;

System Architecture & 4-Level Partitioning

The save system organizes state using a deterministic, case-insensitive 4-level dictionary hierarchy:

fileName -> entityId -> componentId -> variableName -> value
  • FileName (string): Identifies the save file / partition (e.g., "core", "room_01", "player_inventory").
  • EntityId (string): The persistent GUID assigned to a GameObject via UniqueId.
  • ComponentId (string): The zero-based order index ("0", "1", "2") of IBoundState components on the entity, preventing key collisions when multiple components on the same entity track variables with identical names.
  • VariableName (string): The key associated with a specific Tracked<T> variable or state entry.
  • Value (object): The stored primitive, vector array, or JSON-serializable value.

Serialized JSON Structure

{
  "8f9a2b1c-3d4e-5f6a-7b8c-9d0e1f2a3b4c": {
    "0": {
      "health": 100,
      "maxHealth": 100
    },
    "1": {
      "body_position": [ 12.5, 0.0, -4.2 ],
      "body_rotation": [ 0.0, 90.0, 0.0 ]
    }
  }
}

Reference-Counted File Lifecycle & Event Architecture

Blackboard manages save files in memory using BlackboardFile instances with explicit reference counting (RefCount) and a deterministic execution hierarchy:

SaveSystem (-1200)
→
Blackboard (-1100)
→
BlackboardScope (-1000)
→
BlackboardClient (0)
  • Blackboard holds Files (Dictionary<string, BlackboardFile>), provides direct O(1) lookup (GetOrCreateFile) for clients, and exposes OnDeactivate (event Action) to force active BlackboardScope instances to release if Blackboard disables.
  • BlackboardFile holds its Data (FileContainer dictionary), RefCount, OnUnload (event Action) for BlackboardClient instances, and all file unload and disk serialization procedures.
  • BlackboardScope is a pure RAII smart pointer (MonoBehaviour) that anchors configured files in RAM while enabled and has zero awareness of clients.
  • BlackboardClient is a pure leaf data proxy that subscribes directly to its BlackboardFile.OnUnload event.
                  AcquireFileSync() (RefCount == 0)
                     ├──> Read file from disk into BlackboardFile
                     └──> Set file.RefCount = 1
  ┌───────────────┐
  │ BlackboardFile│  AcquireFileSync() (RefCount > 0)
  │ (In RAM)      │  └──> Increment file.RefCount (No disk I/O)
  └───────┬───────┘
          │          ReleaseFileAsync() (RefCount > 1)
          │          └──> Decrement file.RefCount (Keep in RAM)
          │
          └─────────> ReleaseFileAsync() (RefCount == 1 -> 0)
                     ├──> file.NotifyUnloading() -> invokes OnUnload on subscribed Clients
                     ├──> Remove BlackboardFile from Blackboard.Files
                     └──> file.SerializeAsync() writes JSON to disk

API Reference: Blackboard & BlackboardFile

BlackboardFile Class

Encapsulates a single save file's in-memory dictionary, reference count, and unload lifecycle events.

public class BlackboardFile {
    public readonly string        Name;
    public readonly FileContainer Data;
    public int                    RefCount { get; set; }
    public event Action           OnUnload;

    public BlackboardFile(string name, FileContainer data = null);
    public void CollectData();
    public void NotifyUnloading();
    public EntityContainer GetOrCreateEntity(string entityId);
    public Partition GetPartition(string entityId, string componentId = "0");
    public Task SerializeAsync(Action<string> onFailure = null);
    public static FileContainer ReadFromDisk(string fileName, Action<string> onFailure = null);
}

API Reference: BlackboardScope

BlackboardScope ([DefaultExecutionOrder(-1000)]) is a pure RAII MonoBehaviour smart pointer that anchors configured BlackboardFile instances in RAM while enabled and subscribes to Blackboard.OnDeactivate.

public List<string> fileNames

List of Blackboard file names to keep loaded in RAM while this scope is enabled.

public void AcquireScope() public Task ReleaseScopeAsync()

Acquires file leases on OnEnable and releases them on OnDisable (or when Blackboard.OnDeactivate fires).

API Reference: BlackboardClient & IBoundState

BlackboardClient ([DefaultExecutionOrder(0)]) is a pure leaf-node data proxy between local IBoundState components on a GameObject and its target BlackboardFile. Requires a UniqueId component. 

public interface IBoundState {
    void OnLoadState(Partition state);
    void OnSaveState(Partition state);
}
public string fileName public string EntityId { get; }

Target save file name and the persistent GUID retrieved from UniqueId.

public void FlushStateToBlackboard() public void LoadStateFromBlackboard() public Partition GetPartition(int componentIndex = 0) public Partition GetPartition(string componentId)

Flushes or restores all local IBoundState components into component-indexed partitions ("0", "1", ...). Automatically subscribes FlushStateToBlackboard to BlackboardFile.OnUnload while enabled.

API Reference: TrackedBehaviour & Tracked<T>

public interface ITracked {
    string Key { get; }
    void Save(Dictionary<string, object> state);
    void Load(Dictionary<string, object> state);
}

public class Tracked<T> : ITracked {
    public T Value { get; set; }
    public Tracked(string key, T defaultValue);
    public static implicit operator T(Tracked<T> tracked);
}

public abstract class TrackedBehaviour : MonoBehaviour, IBoundState {
    public virtual void OnSaveState(Dictionary<string, object> state);
    public virtual void OnLoadState(Dictionary<string, object> state);
    protected virtual void OnAwake();
}
